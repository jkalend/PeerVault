# ADR 0002 — V0.4 keep-both sync decision

- Status: accepted for the backup-only 0.9 path; V0.7 sync remains open.
- Date: 2026-11-01
- Decision owner: PeerVault implementation maintainer

## Decision

Do **not** adopt a live-folder sync engine for the first supported release.
Continue the backup-only 0.9 path and keep V0.7 opt-in sync as a separately
qualified branch. No sync behavior, conflict guarantee or tombstone-supported
deletion is claimed by this repository.

## Context

Backup repository replication is not live-folder synchronization. A sync engine
must express causal operation identity, deterministic keep-both conflict
artifacts, tombstone horizons, pre-delete capture/versioning, replay/reorder
recovery and explicit discovery/relay/telemetry controls. A wrapper cannot invent
a guarantee the engine does not expose.

This decision is a capability decision. No sync engine build was installed or
fault-tested for V0.4; dated documentation and the release plan were scored, and
that is recorded as a residual evidence gap rather than a pass.

## Candidate scoring

| Requirement | Syncthing (documented) | rclone bisync (documented) | Backup backend | Custom protocol |
|---|---|---|---|---|
| Causal operation identity | not exposed | not exposed | not a live sync engine | would require a reviewed design |
| Keep-both conflict artifact | native conflict copies, clock-dependent names | no guaranteed conflict record | not applicable | design required |
| Tombstone horizon / deletion source | not exposed as a backup authority | not exposed | no live delete propagation | design required |
| Pre-delete capture/versioning | external versioner only; not a PeerVault backup guarantee | not exposed | backup history exists, but not a sync seam | design required |
| Replay/reorder/partition fault seam | no documented deterministic seam | not exposed | no live transfer | design required |
| Discovery/relay/telemetry controls | native discovery/relay options with residual exposure | external configuration | not applicable | design required |
| License/redistribution | MPL-2.0 engine; separate packaging review | MIT engine; separate review | selected restic BSD-2-Clause | first-party design/review |
| Verdict | wrapper cannot enforce the full safety set | not viable as a safety seam | not live sync | not approved |

The pre-approved supported backup-only 0.9 path is selected instead of forcing a
sync engine whose required safety rules cannot be expressed. This is not a claim
that Syncthing or rclone are unusable products; it is a claim that neither is
qualified as PeerVault's supported sync seam here.

## Consequences

- V0.7 sync stays open; V0.8 scheduling/status and V0.9 measured recovery target
  the backup-only scope.
- No conflict/tombstone/retention behavior is enabled for live folders.
- A future sync proposal must pin an exact engine build, test the safety matrix
  on isolated devices, and record replay/reorder/partition/clock-skew evidence.
  A wrapper that cannot observe the engine contract is not a substitute.
- Peer repository copies remain backup copies, not live-folder sync.

## Residual evidence

- No exact sync-engine build, fault injection or two-device reconnect experiment.
- No second-operator sync usability result.
- Any future supported-sync claim needs the V0.7 gates, not this ADR.
