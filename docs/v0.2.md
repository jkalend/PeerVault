# V0.2 — RecoveryKit and clean-copy drill

Status: experimental RecoveryKit v1 and an author-only same-host copy/recovery
drill. It is not a second-operator usability test, clean-hardware qualification or
a supported release. The kit contains no secrets.

## Commands

```text
peervault recovery-kit generate --repository <repo> --backend <restic> --snapshot <id> --kit <new-dir> [--password-file <path>]
peervault recovery-kit verify --kit <dir>
peervault recovery-kit verify --kit <dir> --repository <surviving-copy> --backend <restic> [--password-file <path>]
```

The inventory-only verify needs no repository or secret. Supplying
`--repository` and `--backend` also checks the repository binding, the exact
encrypted oracle snapshot, the tree/policy evidence and a repository full read.
Reports use schema v1; exit `0` is success and nonzero is a refusal.

## Kit contents

| Member | Purpose |
|---|---|
| `kit.json` | Kit ID, snapshot + stable capture ID, oracle snapshot, repository ID, backend version/hash/acquisition URL, profile, evidence and custody guidance |
| `ACQUISITION.md` | Immutable backend URL, archive/executable SHA-256, publisher-verification instruction; no download-latest |
| `RUNBOOK.md` | Offline acquisition, inventory/full-read verify, exact restore, custody/rotation/cleanup |
| `manifest.json` | Bounded inventory of the other members with size/SHA-256 |

No password, key, plaintext file content or private source path is stored. The kit
inventory is capped at 16 members / 1 MiB per member. A kit self-checksum is not
publisher authenticity.

The tree oracle remains an encrypted restic snapshot. Data and manifest snapshots
share a stable `peervault-capture-id-<id>` tag, so `restic copy` ID changes do not
break the oracle mapping. The kit records both the copy snapshot ID and the stable
capture ID.

## Author-only clean-copy drill

```text
python scripts/v02-clean-drill.py --binary ./peervault --backend .tools/restic \
  --work-root <new-source-host-root> --copy-root <new-independent-copy-root> \
  --recovery-root <new-recovery-root>
```

The script captures a synthetic tree, performs the backend-native `restic copy`,
removes the source tree and source repository, generates the kit from the copy,
verifies the kit with a repository full read, and restores every file/hash into a
new destination using only the copy, kit and separately written secret file.

Observed on 2026-11-01:

| Host | Capture ID | Kit | Full read | Restore |
|---|---|---|---|---|
| Windows/NTFS, copy on G: SATA HDD | `6aec458e746f9ac93c23204801e9582f` | `871d32bb58c4d25fbf7d7001eec5ec91` | pass | exact, 4 files |
| Ubuntu 24.04/ext4 WSL2, copy on G: | `ef34202eaaf5f0350876a12a1d94b34b` | `68f5a24e3773ce1ad3ab01fd111b5de4` | pass | exact, 4 files |

Both runs used distinct source/copy roots, removed the source material before kit
generation and restore, and retained the secret outside the kit. They remain
author-only and same-host; the Ubuntu copy medium was G: through WSL, and the
recovery root was virtual ext4.

`scripts/v02-kit-smoke.py` runs in CI: generate, inventory verify, bound full-read
verify, wrong-secret refusal and tamper refusal.

## Tested refusals

- Missing/changed/extra kit member and duplicate/traversal inventory path.
- Wrong repository secret; repository-ID or oracle-snapshot mismatch.
- Tampered `RUNBOOK.md` after generation.
- Missing oracle and ambiguous oracle tags.

## Not claimed

- A second operator can follow the kit without author help.
- Network is disabled by the script; the kit avoids network dependencies, but the
  drill does not enforce a network namespace.
- Clean hardware, physical source-disk removal, offsite custody or removable-media
  identity/eject/reconnect behavior.
- Credential rewrapping, transport revocation or data-key rotation; a former
  key-holding device can still read what it copied.
- Historical snapshots after credential changes, replaced/removed devices or a
  leaked-key revocation procedure.
- The kit is not a publisher signature, Merkle proof or defence against a
  compromised backend that rewrites data and oracle snapshots.
