## Result matrix

`scripts/v06-matrix.py` captured a supported tree, restored it exactly, then
injected unsupported entries and metadata. Both runs passed.

| Case | Windows/NTFS | Linux/ext4 | Restore behavior |
|---|---|---|---|
| Regular files, directories, empty file | supported | supported | exact path/type/size/SHA-256 |
| Unicode NFC and NFD names | supported | supported | literal bytes; no normalization |
| Long path (three 80-byte components) | supported | supported | handled below the 1024-byte/16-level policy |
| Read-only bit | supported | supported | reproduced on owned files |
| Hard link | lossy | lossy | content stored twice; link identity lost |
| NTFS alternate data stream | lossy | n/a | stream not captured or restored |
| POSIX xattr | n/a | lossy | xattr not captured or restored |
| Timestamps | lossy | lossy | mtime is outside the restore oracle |
| Symlink | rejected | rejected | capture fails before publication |
| Reparse point | rejected | n/a | capture checks the Windows attribute |
| FIFO/special file | n/a | rejected | capture fails before publication |
| Case-insensitive collision | n/a (filesystem prevents) | rejected | capture fails before publication |

The supported capture contained 10 files and 5 directories on both profiles,
including `composed-é.bin`, `decomposed-é.bin` (U+0065 U+0301),
`unicode-žluťoučký-雪.txt`, an empty file, a 2 MiB binary and the long path.

After each refused capture, history still contained the prior complete capture
with its oracle, and that snapshot restored exactly. No refused capture published
a complete oracle. This confirms unsupported selected content fails visibly
rather than silently under-protecting it.

`scripts/v06-cross-os.py` additionally captured on Windows and restored on Linux,
then captured on Linux and restored on Windows, using the same portable subset
and independent SHA-256 oracle. Both directions passed (6 files, 2 directories).
This is same-host WSL2 evidence; it does not replace independent hardware.

The V0.1 smoke and this matrix also passed in a fresh `ubuntu:24.04` Docker
container with Python 3 and the pinned Linux restic, using `/work` inside the
container. That removes the WSL 22.04 version gap but is still a container on
the same host, not a clean Ubuntu 24.04 installation or independent hardware.

`scripts/v06-upgrade.py` created a repository with the previous commit's binary,
read/restored that snapshot with the new binary, captured a new snapshot, and
read/restored it with the old binary. Both directions passed. This is a
repository-format/CLI compatibility rehearsal between two commits, not a
released-version upgrade or irreversible backend migration.

`scripts/v06-capacity.py` ran capture and restore under `RLIMIT_FSIZE`; the
limited capture failed, a limited restore left no complete target, and the
unlimited baseline restore stayed exact. This is quota-style file-size
exhaustion, not physical disk-full or power loss.

## Published subset

Supported source and target mapping:

- regular files: bytes, size and SHA-256;
- directories, including empty directories;
- UTF-8 portable relative paths up to 1024 bytes and 16 components;
- case-insensitive collision rejection;
- read-only bit on restored owned files.

Rejected or explicitly lossy:

- symlinks, Windows reparse points and special files are refused;
- hard-link identity, NTFS streams/ACLs, POSIX owners/xattrs/modes beyond the
  read-only bit, timestamps, sparse allocation and alternate data streams are
  not preserved;
- names that differ only by case are refused; there is no winner or silent
  rename;
- VSS, network shares, cloud-synced roots, offline placeholders and automatic
  hydration are outside this matrix.

## Still open for V0.6

- Scoped VM hard-power-off, physical disk-full, denied access and index rebuild;
  the `RLIMIT_FSIZE` drill is quota-style only.
- A corpus rerun within the declared limit; the 2026-11-01 pass (664.5 s) and the
  2026-11-03 failure at 900 s are both retained.
- A clean Ubuntu 24.04 **installation/host**; the container passes V0.1 and the
  matrix, but shares the host kernel and hardware.
- Independent beta, second operator and independent hardware.
